# Windows 采集、训练、识别代码调研

调研日期：2026-11-26。范围按本次要求限定为：沿用 NERO；新数据使用人工按压快速采集；训练无需操作者填写命令行参数；识别使用最新模型。本文不讨论环境安装、驱动安装或离线依赖打包。

参考了本机 `WAIC_2026_RealMan_RM_API2_Windows_20260803_FINAL_CLEAN` 的入口组织方式。它的 RealMan 网络控制、动作坐标与 RM_API2 不适用于本项目。此次只借鉴“给操作者明确入口、自动检查输入、显示可读结果”，不移植机械臂控制。

**交付状态：本文是已核对源码的改造方案；下面列出的 Windows 新入口与一键训练器尚未实现。** 本次远端同步包含已有采集、纠错、训练代码，以及最新模型的可移植默认路径。

## 三个操作入口

| 流程 | 操作者应看到的操作 | 复用现有代码 | 需要补充的代码 |
| --- | --- | --- | --- |
| 人工快速采集 | 打开“采集”→选择传感器和生肖→手工按压→空格保存；R 连拍、Esc 停止、Z 撤回 | `collect_manual.py`、`core/manual_collection.py`、`gui/manual_collection_canvas.py` | Windows 进程锁、正确的默认配置、相机选择、双击入口 |

采集与人工识别都不需要机械臂运动。原 NERO 识别入口保留，选择人工流程时不要求连接 NERO。

## 已确认的 Windows 代码缺口

### 1. 快速采集不能只把 `.sh` 换成 `.bat`

- `collect_manual.py` 无条件调用 `core.instance.desktop_instance()`；该函数内部导入 `fcntl`，因此在 Windows 会失败。应保留 Linux 的 `flock`，增加 Windows 互斥实现，并覆盖正常退出、崩溃释放、第二实例提示。Python 官方明确将 `fcntl` 限定为 Unix；Windows 可选用 `msvcrt.locking` 或命名互斥体。[fcntl 文档](https://docs.python.org/3.12/library/fcntl.html)、[msvcrt 文档](https://docs.python.org/3.12/library/msvcrt.html)。
- 采集默认读取 `config/ubuntu/config.yaml`，其 `preferred_camera_name` 为 VBTS；而 `core/camera.py` 当前只在 Linux 读取设备名称，Windows 名称为空。自动匹配会找不到设备。Windows 应使用自己的默认配置，并让用户从能读出图像的设备列表选择；不能默认为电脑内置摄像头。
- 相机代码已有 Windows DirectShow / MSMF 后端和 1600×1200 请求，保存时也已有 180° 统一旋转及无损原图。复用这条链路，验证 Windows 实际返回的分辨率与方向，避免额外旋转或用预览 JPEG 训练。
- 快速采集不做空载校准、不加载模型，标签由操作者选择。保留十二生肖、未知物体、空载标签和已有 `session.json` / `samples.jsonl` 格式；不要改成依赖机械臂的 `collect_gui.py`。

建议新增 `tools/start_manual_collect_windows.bat`，默认参数在代码内处理。选相机和标签属于采集操作，操作者不需要编辑 YAML。

### 2. 一键训练需要完整编排

建议新增 `train_easy.py` 和 `tools/train_windows.bat`，把 `train.py` 保留为高级入口。简单入口应完成以下流程：

1. **自动查找输入。** 读取上一轮已登记的训练数据快照、`data/manual/` 新采集会话和 `data/corrections/` 纠错会话。只处理清单中仍有效的图像，忽略 `_undone`，不把导出图、预览图或已删除的误标图重新加入训练。
2. **可读预检。** 显示各生肖的新旧图像数量；检查缺图、错误标签、重复像素、旋转和会话记录。出现问题时直接给出具体文件和类别。尚无可靠验证数据时，可以生成候选模型，但不能自动替换当前识别模型。
3. **自动选择训练方式。** 有配套 `best.pt` 和旧划分时默认小学习率续训，并混合旧训练图；不让操作者选择学习率、设备编号或 `--reference-split`。自动选可用 GPU，否则使用 CPU；Windows 默认 `workers=0`。数据或训练失败只保留报告，不改当前模型。
4. **固定旧验证集。** 旧图按像素哈希保留分配，不能随机重分来提高分数。新增纠错图按记录的真实按压组划分；快速采集的连拍图目前没有按压分组，应至少按采集会话分组，不能默认一张图就是一次独立按压。历史数据的分组方式和新数据分组方式需分别处理，不能用全局 `--manual-grouping frame` 一次覆盖。
5. **自动导出与对比。** 导出 ONNX 和配套清单，检查 PyTorch/ONNX 一致性，再分别回放旧验证集、新留出集、训练纠错图。显示每类正确数、旧图新出现的错误和低于 50% 的数量。训练纠错图的成绩标为“训练回放”，不能当作独立验证准确率。
6. **有条件更新识别。** 默认要求旧验证图不新增错误或低置信度失败、纠错表现有改善、模型加载检查通过，才切换成套模型。完整未知物体/空载验证不足时仍保留预览模式，不能绕过现有正式发布门槛。不能直接给 `train.py` 加上 `--deploy`，因为目前这套数据未满足正式拒识验证条件。
7. **保存与恢复。** 每次生成独立运行目录、数据快照、划分、参数、逐图对比和前一模型指针。识别程序在重新加载前读到的必须是同一版本的 ONNX 与清单；建议写入完整版本目录后原子替换一个小的模型指针。提供“恢复上一版”，训练中断不破坏正在使用的版本。

只有“15 张纠错图都记住了”不能证明原能力保持。默认只训练一次并保留新验证图；如果后续决定让全部纠错图参与最终拟合，必须撤销这些图的留出属性，单独记录最终模型的训练回放结果。

**续训还需要旧数据，单靠权重无法检查是否遗忘。** 仓库已带最新 `best.pt` / `best.onnx` / `best.json`，但真实采集数据和 `runs/` 没有提交。Windows 首次保守续训必须同时拿到原训练/验证图像及对应划分索引。应增加一次性数据包导入：用相对路径和像素哈希登记，而不是携带本机 `/home/...` 绝对路径。缺少这个包时，界面应明确提示“缺少旧验证数据，不能自动保证旧识别保持”，不得静默改成只用新纠错图训练。

### 3. 识别可以复用现有人工 GUI

现有源码已经支持在 Windows 使用人工连续识别和纠错页面：

```powershell
.\.venv-runtime\Scripts\python.exe desktop_main.py --manual --config config/raw/config.yaml
```

这是当前代码支持的调用路径，尚未在本次会话的 Windows 真机上验证。建议用 `tools/start_manual_test_windows.bat` 封装该命令，并复用采集的相机选择与进程锁。

识别统一读取最新 `models/raw/best.onnx` 和 `best.json`，预览模式、50% 门槛、接触稳定与连续帧确认沿用现有逻辑。纠错继续保存完整原图、真实标签、模型版本、预测和位置备注到 `data/corrections/`，供下次一键训练自动发现。

Windows 默认 `desktop_main.py` 走另一套原生桌面 GUI；它没有接入人工纠错页面。`TouchSign-desktop.spec` 还排除了 NiceGUI，因此现有 `TouchSign-Desktop.exe` 不能直接通过 `--manual` 获得这些功能。此次三流程方案优先复用源码人工 GUI，不把旧 EXE 当作功能已齐全的交付物。

## 建议实施顺序与验收

| 顺序 | 改动 | 验收结果 |
| --- | --- | --- |
| 1 | Windows 快速采集兼容、配置和相机选择 | 空格保存、连拍、撤回、中文路径、退出释放相机正常；保存图方向与 Linux 一致 |
| 2 | 旧数据与划分导入、一键训练器 | 无需填写训练参数；旧验证图始终留出；失败可重试且不覆盖当前模型 |
| 3 | 人工识别入口和模型切换 | 自动加载本次模型；误判能标注保存；再次训练可读到纠错样本；可恢复旧模型 |
| 4 | Windows 端完整闭环 | 采集一批 → 一键训练 → 查看旧/新结果 → 识别 → 保存纠错 → 再训练，全程不操作机械臂 |

本次 Linux 自动测试不能替代上述 Windows 验收。当前发布模型来自 `corrections_final_raw_20261126_121349`，摘要及文件哈希见 [models/raw/release.json](../models/raw/release.json)。
