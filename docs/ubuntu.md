# Ubuntu 运行与本机硬件验证

支持 Ubuntu 24.04 / Python 3.12。Ubuntu 使用中文 NiceGUI 浏览器界面和 Linux SocketCAN；Windows 继续使用原有 WebView2 与 USB-CAN 驱动。

## 安装与启动

在项目目录运行：

```bash
# 缺少系统依赖时安装；已有环境可跳过。
sudo apt install python3-venv python3-pip libgl1 libglib2.0-0 fonts-noto-cjk v4l-utils can-utils
bash tools/setup_ubuntu.sh
bash tools/start_ubuntu.sh
```

启动脚本使用项目 `.venv-runtime`，不修改系统 Python，并清除当前终端继承的 ROS `PYTHONPATH`，避免 ROS 包混入运行环境。Ubuntu 不需要 WebView2、Windows DLL 或 PyQt/GTK 浏览器组件。

指定端口，或者只启动后台服务：

```bash
bash tools/start_ubuntu.sh --port 8080
bash tools/start_ubuntu.sh --no-show --port 8080
```

默认固定使用 `http://127.0.0.1:8080`，也可通过 `--port` 指定。Ubuntu 桌面入口使用进程锁：重复启动会打开已有实例并退出，不再启动第二个摄像头采集进程；异常退出后锁由系统自动释放。点击“退出程序”或在终端按 Ctrl+C 关闭程序。关闭浏览器页面会释放该页面使用的传感器，但本地服务仍会运行。

退出信号到达后，实时视频流主动结束；其他 HTTP 长连接最多等待三秒，再执行资源清理。机械臂保持指令失败会记录错误，仍继续关闭 CAN 和相机。排查占用时应确认终端已返回命令提示符。

默认读取 `config/ubuntu/config.yaml`，并只探测名称匹配 VBTS 的传感器。本机当前加载 `models/raw/best.onnx` 及同目录的 `best.json`（与 `runs/corrections_final_raw_20261126_121349/` 导出逐字节一致），在上一轮鸡类补训模型基础上加入了 11 月 26 日人工标注的 15 张纠错图。最新 `best.onnx`、`best.json` 和续训用 `best.pt` 已同步到 Git 跟踪的 `models/raw/`；新克隆默认即可加载相同权重，发布摘要见该目录的 `release.json`。完整训练数据和 `runs/` 仍仅保存在本机。模型仍处于预览模式，未启用基于特征距离的完整拒识；人工测试及机械臂最终确认都会检查置信度门槛。传感器空载时点击“空载校准”，再接触生肖牌。不同型号传感器可以修改 `sensor.preferred_camera_name`；设为空字符串后会扫描全部兼容摄像头，供界面中手动选择。

本次数据快照共 423 张：原有 408 张加 15 张纠错图（鼠 2、牛 2、虎 1、龙 5、羊 4、猴 1），来自 15 次不同按压。原 319 张训练图全部参与混合续训，原 89 张验证图始终留出，之前删除的误标狗图仍排除。先以学习率 0.0001 做 11 张纠错训练 / 4 张纠错验证的诊断试训，纠错验证由 0/4 提升至 3/4，剩下一张鼠图误判羊；该阶段记录在 `runs/corrections_raw_20261126_120851/`。随后将全部 15 张纠错图纳入最终训练，用学习率 0.00005、偏置预热学习率 0 续训 16 轮，最终为 334 张训练、89 张验证。诊断阶段的 4 张纠错验证图在最终模型中已是训练图，不能再作为留出成绩。

最终 ONNX 按当前 50% 门槛离线回放：原验证集仍为 89/89，最低正确类别置信度由 78.09% 变为 95.53%；原训练图保持 319/319，其中空载 5/5；此前额外留出的鸡图保持 13/13。纠错图从 0/15 达标变为 15/15，最低置信度 99.87%，这是训练拟合检查，不代表新按压的泛化准确率。原验证集用于选取权重，额外鸡图未参与训练和轮次选择；不同位置与姿态仍需实机复测。详细输入、参数、逐图对比和运行检查见本机 `runs/corrections_final_raw_20261126_121349/` 的 `input_audit.json`、`training_job.json`、`comparison.json`、`verification.json`。缺少未知物体及独立空载验证，保持预览模式。旧模型保留在 `runs/rooster_raw_20261125_181814/`，更新前配置保存在该运行目录的 `previous_ubuntu.yaml`。完全退出旧程序后运行 `bash tools/start_manual_test_ubuntu.sh`，即可在人工测试 GUI 加载新模型。

机械臂最终确认门槛按用户要求设为 **50%**（`recognition.confidence_threshold: 0.50`）。低于门槛时继续识别，并提示当前候选与置信度；低置信度帧会清空连续确认计数，超时则报告本轮未识别，不播报候选生肖。达到门槛后仍须接触稳定、多个新帧一致；这不是正式模型的未知物体拒识验证。

## 人工按压识别测试

需要大量重复测试时，先退出正在运行的 TouchSign，再启动原连续识别 GUI：

```bash
bash tools/start_manual_test_ubuntu.sh
# 等价命令，也支持 --config、--port 和 --no-show
bash tools/start_ubuntu.sh --manual
```

该入口读取同一份 `config/ubuntu/config.yaml`，关闭机械臂控制，使用人工按压测试标题；模型路径、配套清单、接触检测参数和相机配置均沿用当前设置。当前权重为 `models/raw/best.onnx`，对应 `corrections_final_raw_20261126_121349` 训练批次。以后更新 Ubuntu 配置的模型路径，人工入口也会加载该模型，无需另改一份配置。

界面中没有机械臂连接、检测一轮或示教按钮。连接 VBTS → 移开所有物体 → 点击“空载校准” → 压稳牌子查看结果 → 松开后再次按压。持续自动识别，无需每次点击检测。松开会清空当前结果；同一生肖再次播报需要连续松开至少 0.5 秒。语音可以关闭以便快速测试。

图像仍在相机发布时统一旋转 180°；当前原图模型使用旋转后的 BGR 原图，经全图等比例缩放和补边至 224×224、BGR→RGB、除以 255 后进行 ONNX 推理。差分图用于空载基线与接触稳定检测；切换预览画面不会改变模型输入。人工测试复用当前识别引擎，并保留当前机械臂预览的确认条件：达到配置中的置信度门槛（当前 50%），至少 3 个新帧类别一致且持续至少 0.15 秒。低置信度、接触不稳、类别变化或帧中断会重新确认。

当前权重仍是未完成完整拒识验证的预览模型，人工测试结果标注为“模型预览”，不写入正式 `logs/recognition.csv`。相机断流、重连或切换后需重新空载校准。切回机械臂测试时退出程序，再运行原来的 `bash tools/start_ubuntu.sh`。

### 保存误判图像和正确标签

发现特定按压位置识别错误时，保持按压并点击工具栏的 **“保存纠错样本”**。弹窗冻结最近完成识别的原图及该帧预测，之后可以松开实物：

1. 核对冻结图像和显示的预测生肖、置信度。
2. 在“实物的正确生肖”中选择真实标签。此项不会自动填入模型预测。
3. 可填写位置或姿态，例如“右上角，向左倾斜时误判”。
4. 点击“按正确标签保存”，成功后继续测试；取消不会写入样本。

置信度不足或仍在连续确认的帧也可标注，只要已经完成推理并有有效接触。没有新鲜识别帧、信号中断或设备切换时不能冻结旧画面；已经打开的弹窗保留其原始图像和预测，即使松开实物或实时画面变化，保存的仍是弹窗中这一帧。写盘失败会保留冻结图像供重试，同一帧不会重复写入。

纠错数据独立保存到 `data/corrections/<时间_会话ID>/<正确英文标签>/*.png`，工具栏显示本次页面已保存数量。图像是完整分辨率、无文字叠加的无损原图，沿用相机已完成的 180° 旋转，不再二次旋转。`session.json` 和 `samples.jsonl` 兼容现有手工原图格式；清单的 `label` 是人工正确标签，`correction` 中额外记录该帧的原始模型预测、候选与置信度、模型路径与 SHA256、接触中心和面积、位置备注及按压分组。

现有训练读取器使用 `--input raw` 可以读取这些会话。后续针对性训练需将选中的纠错会话与原训练数据合并，并沿用原模型的 `--reference-split`，避免旧验证图进入训练；只有个别生肖的纠错数据不能单独替代完整训练集。即使使用 `--manual-grouping frame`，同一次持续按压保存的多张纠错图仍按同一组划分；松开后重新按压才开始新组。此功能只保存样本，不会自动训练或替换当前模型。大量按标签采集新图仍可使用 `start_manual_collect_ubuntu.sh`。

## 传感器

手工按压快速采集使用 `bash tools/start_manual_collect_ubuntu.sh`：选标签后按空格保存，R 连拍、Esc 停止，无需机械臂或校准；图像旋转 180° 保存。详见 [手工采集说明](manual-collection.md)。

需要采集训练数据时，退出识别程序后使用 `bash tools/start_collect_ubuntu.sh`。新界面复用相同的机械臂动作与相机预览，增加人工标签和自动/手动采样；详见 [采集与标注流程](collection-gui.md)。

采集图像统一旋转 **180°** 后，再供识别、空载校准和界面展示使用；原图、差分预览、浏览器 MJPEG 和桌面预览方向一致。更新后完全退出并重启程序，再进行一次空载校准。

Linux 按实际 `/dev/video*` 节点扫描，不再限制为 0–5 号，并显示内核提供的设备名称。Ubuntu 配置按 `VBTS` 名称匹配，拔插后编号变化也可以找到；缺少 VBTS 时不会自动改用普通摄像头。

扫描先查询 V4L2 节点能力与格式，跳过元数据节点以及不支持常见彩色格式的深度/红外节点。VBTS 的 `/dev/video9` 是元数据节点，不能用于图像采集。彩色节点读取失败时，设备仍列在清单中并显示占用提示。若 `/dev/video8` 无法打开，可运行 `fuser -v /dev/video8` 查看占用进程，先退出对应的旧 TouchSign 或其他相机程序，再刷新设备列表。

```bash
v4l2-ctl --list-devices
.venv-runtime/bin/python main.py --list-cameras
.venv-runtime/bin/python -m tools.check_hardware --camera 8
```

`8` 是本次检测时的编号，重连后应以设备清单为准。程序在 Linux 请求 MJPEG、1600×1200、30 FPS，并使用单帧采集缓冲；实际处理帧率取决于设备、USB 带宽与 CPU。VBTS 的 YUYV 格式在这个分辨率下只提供 5 FPS。

## 机械臂

在“展开机械臂设置”中填写 SocketCAN 网口名称。本机使用 `can_follower`，已保存至 `~/.local/share/TouchSign/config.yaml`。若设置了绝对路径 `XDG_DATA_HOME`，则配置保存在 `$XDG_DATA_HOME/TouchSign/config.yaml`。新环境默认 `can0`。

本机 NERO 使用 1 Mbps。网口处于 DOWN 时，在本机终端执行：

```bash
sudo ip link set can_follower type can bitrate 1000000
sudo ip link set can_follower up
ip -details link show can_follower
```

程序不会自行运行 sudo 或修改 CAN 网口。接口已启用时不要重复修改波特率；重启或拔插后先查看状态。`ERROR-ACTIVE` 是 SocketCAN 的正常主动状态，不等同于机械臂故障。

仅被动监听两秒，不发送任何 CAN 指令：

```bash
.venv-runtime/bin/python -m tools.check_hardware --can-channel can_follower --report /tmp/touchsign-hardware.json
```

GUI 每次启动仍默认离线模拟。选择 NERO 真机并连接只建立通信、查询固件与读取反馈，不自动使能；连接时最多等待两秒接收初始反馈。

`#0 · disconnected · 未连接；默认离线模拟` 是初始状态，不是具体故障原因。连接失败后，状态栏会保留 `连接失败：具体原因`，完整异常及 CAN 通道写入 `~/.local/share/TouchSign/logs/desktop.log`。硬件诊断报告同时记录监听前后的 CAN 状态、收发计数和错误帧；网口 `UP`、`ERROR-ACTIVE` 只能说明本地接口状态，不能证明机械臂在线。若网口已启用但有效帧为零、固件查询也超时，应排查 CAN 通信，不能通过重新训练模型或增加识别等待时间解决。

首次连接后，若仅上报 `JOINT_BRAKE_NOT_RELEASED(0x6)` 且关节故障码为零，界面显示“等待使能”，允许点击“开始重力补偿示教”。该按钮会使能机械臂、确认状态恢复正常、张开夹爪，再切换拖动示教。操作前扶稳机械臂并清空夹爪区域；只有界面显示“原生拖动示教”后才开始拖动。若抱闸未释放或出现其他故障，流程停止；此前已成功使能的连接再次上报抱闸状态也按故障处理，不能绕过。

使能后、张开夹爪和切换示教前，程序读取七个关节的实际限位。每个关节最多查询三次，每次等待一秒，重试间隔 50 毫秒；显式设置 SDK `min_interval=0`，确保重试会重新发送读取请求。全部回复的关节编号、角度范围和时间戳有效后才保存至本次连接。持续超时会显示具体关节编号，并清空本次限位；不会使用默认值、部分结果或上次连接的数据继续自动运动，也不会写入设备限位。

进入/退出示教时，程序最多等待三秒接收切换后的反馈，并确认时间戳连续更新，避免首帧尚未到达就报“缺少 leader joints 反馈”，或把上次示教的缓存当成成功。退出时同样等待普通状态、关节和夹爪反馈恢复。运行期间仍检查反馈是否超过 0.5 秒未更新。普通关节数据不能代替 Leader 反馈来确认示教成功。

固件 1.12 及以上退出示教时，还需要恢复普通 CAN 推送：当前固定版本 SDK 的 `set_follower_mode()` 会关闭该推送，而 `set_normal_mode()` 在这些固件上不执行操作。适配层在切回 follower 后，通过 SDK 原有编码器发送恢复推送请求（`0x151`，`move_mode=0xFF`、`enable_can_push=1`），保留其他模式设置，再保持当前关节位置并等待新反馈。该请求只用于用户明确触发的退出示教/停止流程，连接设备时不会自动发送，也不会再次使能电机。恢复请求发送失败，或普通反馈仍不更新，都按故障处理；缓存中的 `NORMAL` 不能视为退出成功。

若 `ip -details -statistics link show can_follower` 显示 `ERROR-PASSIVE`，且被动监听只有带 `is_error_frame=True` 的 `0x24`，这是 CAN 控制器/应答错误，不是示教关节数据。需要先恢复 CAN 通信，再复验示教；单纯增加等待时间不能解决。程序已退出、机械臂已扶稳后，可先重新启用电脑 CAN 接口（保持 1 Mbps）；若错误持续，需检查机械臂控制器和 CAN 物理连接。

```bash
sudo ip link set can_follower down
sudo ip link set can_follower up
ip -details -statistics link show can_follower
```

若仍提示“切换示教超时”，说明尚未确认模式切换，不能继续保存点位。日志 `~/.local/share/TouchSign/logs/desktop.log` 会记录切换方向、通道及失败原因。固件 1.22 使用 `v121` 适配，Leader 反馈对应 `0x155/0x156/0x157/0x170`（[官方固件说明](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/nero/firmware_reference.md)）。停止或断开后再读取 CAN，只能反映之后的状态，不能用来判断先前切换瞬间是否成功。

## 检测完成与停止本轮

一次正常检测按“到检测点 → 夹爪按设定限速闭合至目标间距 → 确认到位 → 保持间距并进行触觉识别 → 张开夹爪 → 确认触觉无接触 → 收回点”执行。显示/播报生肖只表示识别结束，整轮结束以“本轮完成”为准。夹爪张开后还需要新的无接触反馈持续满足稳定时间；默认最多等待 5 秒。主界面会显示当前是在等夹爪张开、新反馈，还是无接触确认；超时会显示具体原因，不会强行收回。

实时图像处理每 50 ms 尝试一次，只处理新帧，上一帧未完成时不排队。接触检测保留原分辨率和阈值，使用 OpenCV 加速通道最大值与接触中心计算。机械臂识别阶段取消原来额外的 0.8 秒等待：正式模式复用识别引擎的多帧确认；预览模式仍要求接触稳定后至少 3 个不同时间戳的同类有效帧，跨度至少 0.15 秒。拒识或类别变化会重新计数。夹爪到位检查、接触稳定时长、断流校验及松开确认保持原规则；日志增加“触觉结果确认”的到位后耗时，便于现场对照。此优化不改变机械运动速度。

上一轮提速的本机离线对照：75 张真实采集图组成的 525 帧序列，优化前后接触判定一致；1600×1200 接触检测中位耗时从 49.6 ms 降到 11.8 ms，当时模型 CPU 推理约 2.6 ms。十二生肖稳定按压的模拟时序回放，从到位到确认由 1.30 秒降到 0.45 秒；该回放不包含 CPU 执行、机械运动和浏览器通信耗时，不等同于实机总延迟。报告保存在 `runs/manual_raw_20261125_merged/` 的 `verification.json`、`latency_cpu.json` 和 `latency_replay.json`；本次重训与门槛测试也未执行机械臂动作。

夹爪参数 `robot.close_width` 表示最终“闭合目标间距”，以米保存，界面以毫米设置。`robot.gripper_close_speed` 是独立的夹爪闭合指令限速，默认 **5 mm/s**（`0.005 m/s`），可在“夹爪闭合限速 mm/s”中设为 1–30 mm/s（30 mm/s 对应 `0.030 m/s`）。机械臂的速度比例控制臂运动，夹爪使用自己的限速。已有配置缺少此项时自动采用 5 mm/s，原有目标间距、夹爪力及点位不变。

[AGX 夹爪 SDK 的宽度指令](https://github.com/agilexrobotics/pyAgxArm/blob/master/pyAgxArm/protocols/can_protocol/drivers/effector/agx_gripper/default/driver.py) 只提供位置和力参数，因此程序每约 50 ms 平滑更新位置目标；默认每次最多减少 0.25 mm，设为 30 mm/s 时每次最多减少 1.5 mm。调度延迟后不补发大幅跳变，命令位置最多领先当前实际闭合位置 2 mm，避免卡住时积累很远的目标。此处是软件位置指令限速，实际机械速度仍取决于设备跟随情况，需在实机上确认；不是固件提供的硬速度上限。

闭合过程中不运行触觉接触判断或识别，也不根据接触或识别结果加力。只有最终目标已下发，且新鲜的夹爪反馈在目标 ±1 mm 内持续满足 `robot.stable_seconds`（默认 0.35 秒），才开始触觉检测；只接受识别阶段开始之后拍摄的新帧。检测期间保持最终目标间距，无接触或未识别不会继续收紧。识别超时无结果时，按正常松开、确认无接触、收回流程结束。

闭合阶段总超时为按初始距离和限速计算的计划行程时间，加上 `robot.grip_timeout` 的等待余量（默认 30 秒），以容纳低速行程。界面和日志显示当前开口、最终间距与限速。到位超时、机械臂反馈无效、相机断流或用户停止时，尝试用实时开口取消未完成的闭合目标，不进入识别。保留正间距限制，禁止目标为零；如保持指令失败，界面提示使用硬件急停。SDK 夹爪力参数保持用户配置，不是经过标定的接触力闭环。张开和停止后松开沿用原有流程；离线模拟压缩夹爪行程时间，不能用于验证实机速度。

旧配置中的 `robot.grip_step` 已停用，读取时忽略，下一次正常保存参数时移除；原有 `close_width`、夹爪力和示教点保持原值。界面不再提供“单步闭合”设置。

“停止本轮并收回”按“中断当前检测/闭合 → 保持当前臂位 → 张开夹爪 → 确认新的无接触反馈 → 返回收回点”执行，完成后显示“本轮已停止，夹爪已张开并返回收回点”，可以再次点击检测，无需断开重连。重复点击不会重复排队，不把取消的检测计为识别成功。示教中、模式切换中或未保存收回点时不可执行。已有检测故障后也可明确点击该按钮尝试松开收回，但必须重新通过实际状态/反馈和接触解除检查，不会自动使能或绕过设备限位。

刚连接、尚未运行检测（`#0`）时，停止并收回会在张开夹爪前读取本次连接缺少的七关节实际限位，并校验收回点，不依赖先运行一轮检测来初始化限位。该准备步骤只查询和校验，不使能电机、不改模式；限位读取失败或点位越界则不继续动作。每次松开开始时清除旧触觉结果，并忽略拍摄于该阶段开始前的迟到结果，等待本次松开后的新帧；旧缓存不会立即触发“信号中断”，也不会被用于确认无接触。一直没有新帧会在松开确认超时后报错，新的帧流编号不符或在本次松开期间过期仍会阻止收回。

断开连接、退出程序或关闭控制页面仍会中止动作并尝试保持当前位置；如果正在执行停止后的松开/收回，则取消剩余动作。夹爪未张开、接触未解除、相机或机械臂反馈异常时，停止后的收回不会继续，界面显示具体原因。按钮流程、故障退出和连接断开在日志中分别记录。
