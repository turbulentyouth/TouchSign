# NERO 单轮触觉检测预览版

## 当前交付方式：ZIP 内只有一个 EXE

请使用 `dist/TouchSign-NERO-SingleFile.zip`，通过 Windows 资源管理器的“全部解压”解压到普通用户目录，再运行其中的 `TouchSign.exe`。不要直接运行构建目录里的 EXE，也不要从压缩包窗口内直接运行。日常使用仍只有一个 EXE，无需携带 `_internal`。

原因：本构建环境输出文件继承 Low Mandatory Level。用户日志证实继承受限权限的 Edge 无法创建普通浏览器配置锁文件（错误码 5，退出码 21），而独立配置也出现权限错误。LocalLow 解压路径只能解决第一阶段临时目录错误，不能消除浏览器进程权限限制。标准 ZIP 不存储该 NTFS 完整性标签，资源管理器解压后的文件继承目标目录权限。未降低系统安全设置，未禁用浏览器沙箱。

构建脚本现在自动生成 ZIP，校验其中恰好一个 EXE、无扩展 ACL 数据、CRC 正确且内容与构建结果一致。桌面浏览器端到端行为仍应以用户解压后的运行结果为准。

检测、停止本轮和红色退出程序按钮均位于空载校准所在操作栏。机械臂连接、示教、模拟和夹爪参数默认隐藏，点击同栏的“展开机械臂设置”显示，点击“收起机械臂设置”隐藏。隐藏仅改变布局，不断开设备、不清除示教点；运行期间停止和退出始终可见。展开区域按内容高度排版，页面可滚动，不再裁切示教控件。

自动打开界面先临时清除打包器设置的 DLL 搜索目录，并过滤浏览器子进程 PATH 中的解压目录，创建子进程后恢复应用 DLL 设置。优先启动已安装的 Edge/Chrome，记录启动器退出码和 browser.log；没有界面连接时自动重试独立的 browser-profile（不修改用户日常浏览器配置，也不禁用浏览器沙箱）。仍未连接才显示地址提示。日志记录请求启动与实际界面连接，两者不会混为一谈。

当前单文件版启动后自动打开浏览器界面，仅监听本机 127.0.0.1，并自动选择空闲端口。实际用户启动日志显示原独立窗口的 Python.Runtime.dll 初始化失败；当前发行配置关闭该窗口模式，避免后台服务已启动但无窗口的情况。界面右上角“退出程序”会关闭后台服务并执行设备清理；仅关闭浏览器标签页不会退出服务。

## 单文件启动修复（当前推荐）

新版 dist/TouchSign-NERO-Preview.exe 仍是一个文件。启动器改用当前用户的 %LOCALAPPDATA%/../LocalLow/TouchSign/unpack 解压，不再依赖 TEMP/TMP。打包运行时的配置、日志、缓存和临时文件统一位于同级 TouchSign 数据目录。无需管理员权限或修改完整性标签。之前 Local/TouchSign 的配置保留不动；新目录首次使用需要重新保存示教点。

## 备用文件夹版

单文件修复验收：31 项相关 Python 测试通过；将 TEMP/TMP 指向普通文件（无法在其中创建目录），并在工作区隔离用户数据路径后，打包 EXE 自检退出码为 0。验证了专用目录解压、日志、缓存、模型、语音和模拟单轮流程。桌面 GUI 交互仍需在用户会话中确认。

若双击单文件版出现 `Could not create temporary directory`，使用 `dist/TouchSign-NERO-Folder.zip`。请在资源管理器中“全部解压”到自己的普通目录，再运行解压后文件夹内的 `TouchSign.exe`，保留旁边完整的 `_internal` 目录。不要在压缩包内直接运行，也不要只拷贝 EXE。

文件夹版无需启动时解压到临时目录。ZIP 不携带构建目录的 NTFS 完整性标签，用户自行解压后文件会继承目标目录权限。构建命令：`.venv-runtime\Scripts\python.exe -m PyInstaller --noconfirm TouchSign-folder.spec`（如当前环境需要 OpenSSL 兼容初始化，仍使用 `gui.runtime.prepare_runtime()` 后调用 PyInstaller）。

本分支为 `feature/nero-teach-detect`，未连接机械臂和触觉传感器进行实测。

## 流程

点击“检测（运行一轮）”后：张开夹爪 → 到检测点 → 闭合压牌 → 稳定识别并显示、播报一次 → 原位松开 → 确认释放 → 返回收回点。结束后等待下一次点击，不自动循环。识别超时同样释放后返回；运动、反馈或释放异常则停止流程，不继续回程。

只保存检测点和收回点，没有过渡点。示教点写入 `%LOCALAPPDATA%/TouchSign/config.yaml` 的 robot 配置，与速度、夹爪参数一起保存，不生成独立示教文件。模拟与不同设备/固件的点位隔离。

## 无硬件试用

1. 启动 EXE，默认选择离线模拟，点击连接。
2. 进入示教，在模拟关节输入框输入七个弧度数值，应用后保存检测点。
3. 设置另一组模拟关节角，保存收回点，结束示教。
4. 选择模拟生肖，点击检测，观察一轮结束。模拟结果明确标注，不写入真实识别记录。
5. 可选择模拟识别超时，验证释放和返回。重复点击不会启动并发任务。

## 真机接入边界

接入松灵 NERO、松灵 USB-CAN 后，选择真机模式并完成界面中的现场确认。连接仅查询状态，不自动使能或运动。示教调用 SDK 原生 leader 拖动模式，退出时以当前关节位置保持；不以断电代替重力补偿。末端夹爪和传感器负载下的重力补偿效果、固件模式切换、实际运动和释放仍须现场验证。

真实检测需要传感器在线、模型就绪和基线校准。只使用本轮闭合后、同一传感器流的新鲜稳定识别结果。释放后需确认夹爪张开和接触消失，再回收。软件停止为尽力保持当前位置，通信中断时不能替代硬件急停。

仅两个点的关节运动不保证末端直线路径；现场必须确保整段运动无障碍。程序没有自动避障功能。

## 打包与验证

SDK、python-can 插件及原始 CAN DLL 随包携带，版本、哈希和许可证见 `vendor/manifest.json` 与 `vendor/README.md`。USB-CAN 的系统驱动及 Windows WebView2 仍需目标电脑具备。构建环境安装 `requirements-build.txt` 后运行 `tools/build_exe.ps1`。

构建中曾出现 Windows 应用控制拒绝加载官方 CAN DLL（WinError 4551）；未更改安全策略。最终重新构建及 EXE 自检均成功加载两份 DLL，并通过 ABI 2 检查。更换电脑后仍需检查驱动和 DLL 加载，离线成功不能证明 USB-CAN 真机通信成功。

打包自检入口：`TouchSign.exe --self-test-report <绝对路径.json>`。自检不打开机械臂或摄像头，检查 ONNX 推理、十二段语音、SDK 固件适配和完整模拟循环。报告分别记录离线结果与 CAN DLL 加载限制。

2026-11-24 验证结果：83 项 Python 测试通过（运行环境完成 82 项，依赖 onnx 的 1 项在训练环境完成）；JavaScript 语音测试通过。122.1 MiB 单文件包自检退出码为 0，ONNX 推理、12 段语音、5 个固件适配配置、CAN DLL 加载与模拟单轮检测均通过。受执行环境网络限制，没有完成 GUI 浏览器交互测试；界面构建测试已通过。真机重力补偿、运动、传感器识别及实际音响播放未测试。
